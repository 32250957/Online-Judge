# 행사 운영 주요 오류 수정

## 변경 내용

- 제출 생성 시각과 DB 세션은 UTC로 고정하고, KST로 입력하는 대회·연습 시각은 비교 전에 UTC로 변환합니다. 대회 경과 시간·페널티·프리즈·구형 연습 기록 집계를 수정합니다.
- CE와 SE를 실행 시간 판정보다 먼저 구분합니다. Docker 실행 실패를 SE로 처리합니다. CE/SE는 대회 오답 페널티에서 제외하며 WA/TLE/MLE/RE는 기존대로 20분을 적용합니다.
- 비공개 대회·비회원 그룹·숨긴 순위·프리즈 이후 타인 제출은 목록, 메인 최근 제출, 상세, 단건/일괄 상태 API와 SSE에 같은 가시성 정책을 적용합니다. 본인과 사이트 관리자는 확인할 수 있습니다.
- 초기 비밀번호 변경 전에는 변경/로그아웃 이외의 동작을 막습니다. 그룹 관리자가 대회 ID로 임의의 기존 대회를 연결하는 경로를 차단합니다.
- Docker 출력은 기본 합계 1MiB까지 수집하며 초과 시 RE와 출력 제한 안내를 반환합니다. 별도 OLE 결과를 추가하지 않습니다. 비정상 종료·출력 초과·시간 초과에도 생성한 컨테이너를 정리합니다.
- 취소/재채점 이후 예전 작업의 결과를 반영하지 않습니다. 하트비트를 별도 스레드에서 보내 장시간 채점 중에도 상태를 갱신합니다.
- 백업 ZIP의 JSON·경로를 먼저 검증하고, FK 순서대로 복구한 후 자동 증가 ID를 보정합니다. bind mount 루트는 유지하고 내용만 교체하며 파일 교체 실패 시 DB와 파일을 복구합니다.
- Compose에 backups 영구 보관을 추가하고 실제 워커 하트비트로 healthy 상태를 표시합니다.
- 일반 사용자의 제출 간격은 기본 2초, 동시 대기/채점 중 제출은 기본 3개입니다. 관리자에게는 적용하지 않습니다.

## 배포

기존 DB·문제·업로드의 백업을 확보한 뒤 웹과 모든 채점 워커를 같은 버전으로 재생성합니다. Compose 환경변수와 기존 볼륨을 유지하세요. 데이터 볼륨 삭제 옵션을 사용하지 마세요.

```bash
docker compose up -d --build
docker compose exec web python tools/regression_check.py
```

환경변수 `OJ_MAX_OUTPUT_BYTES`, `OJ_SUBMIT_INTERVAL_SECONDS`, `OJ_MAX_PENDING_SUBMISSIONS`로 제한을 조정할 수 있습니다. Compose로 값을 변경하려면 해당 web/worker 서비스의 environment에 전달해야 합니다.

과거에 이미 KST naive로 저장된 제출 시각은 자동으로 9시간 보정하지 않습니다. 운영 DB에 UTC와 KST 기록이 섞였다면 백업 후 해당 기록의 저장 기준을 확인해 별도 이관해야 합니다. 기존 timestamptz 컬럼의 보정은 이벤트 입력 시각과 UTC 생성 시각을 구분합니다.

## 백업 복원

1. 행사 제출 접수를 중지하고 모든 worker/worker-2/worker-3/rejudge-worker를 중지합니다.
2. 마지막 하트비트에서 2분 이상 지난 뒤 관리자 백업 화면에서 복원합니다.
3. 복원 후 새 계정·새 제출 생성과 문제 파일을 확인하고 워커를 재시작합니다.

복원 전 ZIP 및 파일 안전 사본은 backups에 남습니다. 실행 중인 워커의 최근 하트비트가 있으면 복원을 거절합니다.

## 검증

`python -m pytest -q`는 기본적으로 격리된 SQLite DB로 회귀 검사를 실행합니다. 운영 DB 주소는 재사용하지 않습니다. `OJ_TEST_DATABASE_URL`에 일회용 PostgreSQL DB를 지정하면 실제 스키마 보정·복원·시퀀스 검사도 실행합니다.

GitHub Actions는 PostgreSQL 16 및 실제 Python/C/C++/Java Docker 이미지를 사용합니다. Docker 검사에는 `OJ_TEST_DOCKER=1`이 필요합니다. 실제 채점, CE/RE/TLE, 출력 초과, 컨테이너 정리와 복원 후 쓰기를 검사합니다.

진행 중 대회의 일시정지, 컴파일 결과 재사용, 프로필 전체 랭킹은 이 수정에 포함되지 않습니다.
